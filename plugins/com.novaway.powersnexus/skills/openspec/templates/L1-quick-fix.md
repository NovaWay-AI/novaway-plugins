# L1 - 快速迭代流程

> 级别：L1
> 名称：快速迭代（Quick Fix）
> 适用：小功能、小优化、Bug 修复、单模块小改动
> 预计耗时：< 30 分钟
> 文档产出：对话内简短假设和验收说明；不创建 OpenSpec 工件

L1 是轻量交付轨道，不是 L2 设计流程的缩小版。除非任务在执行中升级，否则不要加载 `writing-plans`、`openspec`、`red-team`，也不要创建 `tasks.md`。

---

## 流程步骤

### Step 1: grill-me 轻量门禁

- 需求和验收条件清晰：记录一句简短假设，不调用 `question`，立即进入实现。
- 存在会改变实现或验收的关键未知：最多调用一次 `question`；开放式问题使用 `options: []`。
- 发现跨模块、架构、审计或中高风险因素：停止 L1 轨道，升级到 L2+ `brainstorming`，不要在本模板中继续实现。

### Step 2: 记录简短契约

在当前会话中记录以下内容，不写入 `tasks.md` 或其他 OpenSpec 文件：

- 目标：{{要解决的问题}}
- 范围：{{要修改的文件或模块}}
- 假设：{{未阻塞实现的可逆假设}}
- 验收：{{完成条件和需要运行的测试}}

### Step 3: 实现与测试

- [ ] 按简短契约实现功能
- [ ] 保持改动最小并遵循项目代码风格
- [ ] 添加或更新必要的核心测试
- [ ] 运行聚焦测试、类型检查或其他与改动相称的验证

### Step 4: L1 自审

- [ ] 实现是否满足目标和验收条件？
- [ ] 是否覆盖主要边界条件？
- [ ] 是否引入不必要的复杂度或范围扩张？
- [ ] 验证结果是否真实记录了命令和观察到的输出？

如果自审发现跨模块、架构或风险因素，升级到 L2+；不要通过继续堆叠 L1 步骤来规避升级。

### Step 5: 交付

报告简短假设、改动范围、验证命令和结果。提交信息（如用户已授权提交）只需说明变更和验证状态；不要声称未运行的检查已通过。

---

## L1 流程检查清单

- [ ] grill-me 轻量门禁已完成（清晰时零提问，或已使用一次 question）
- [ ] 简短假设和验收说明已记录
- [ ] 实现范围保持在 L1 边界内
- [ ] 相关测试或聚焦验证已运行
- [ ] 完成 L1 自审
- [ ] 如发现升级触发线，已转入 L2+ 设计流程

### 退出条件
- [x] 功能实现完成
- [x] 测试通过
- [x] 自审通过
- [x] 代码已提交

---

## 何时需要升级到 L2+

如果在执行过程中发现以下情况，立即升级：

- 改动超过 50 行 → 升级到 L2
- 涉及多个模块 → 升级到 L2
- 需要设计决策 → 升级到 L2
- 风险等级中等以上 → 升级到 L2
- 需要文档记录 → 升级到 L2
- 用户要求完整流程 → 升级到 L2+

---

## 何时可以降级到 L0

如果发现：
- 实际改动 < 10 行
- 只是 typo/配置/文案
- 不需要测试

**可以降级到 L0 流程**

---

**记住：** L1 是效率和质量的平衡点。如果有任何不确定，立即升级到更高级别。
